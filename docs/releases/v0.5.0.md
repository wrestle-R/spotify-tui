# v0.5.0

2 November 2026 · **Stable** · Linux x86_64 and Apple Silicon macOS

## Music keeps going

Selecting a liked song or playlist row now starts a collection sequence at that
song. Next and previous work through the background Rust helper, so closing the
terminal does not lose the sequence. Ctrl-Right / Ctrl-Left work while searching
as well; n / p remain available outside text input. Previous restarts a song after
three seconds, otherwise moves to the previous entry. A new selection replaces
the local sequence; playback changes from another Spotify controller take over.
Sequences support up to 5,000 playable tracks. Provider context changes can briefly
buffer at a song boundary. P still starts a native playlist from its beginning.

Explore is first in the library and opens at startup, with Spotify's top tracks
when permission is available. Existing logins use local listening history and
liked songs. Press L once to grant the added user-top-read permission. An Explore
or search song starts native Spotify playback, followed by Spotify Autoplay when
that account setting is enabled and suggestions are available. Existing manual
Spotify queue entries keep their normal priority. The provider has no public
autoplay toggle, so the TUI does not claim to switch it on for you.

## A more usable terminal

Press i, ? or F1 for the complete instructions. Scroll with arrows, page keys,
Home/End or the mouse wheel; Esc returns to music. The footer uses readable labels,
and the player has clickable controls. Click collections, songs, search history or
the progress bar; the wheel moves through the pane under the pointer. Hold Shift
to use the terminal's ordinary text selection.

Search shows your last 30 distinct queries. Up/Down recalls a query, clicking one
runs it again, Ctrl-G clears the field and Ctrl-X clears saved searches. Search
history and up to 100 locally played songs stay in an owner-only history.json in
the private state directory. Demo history stays in memory; logout removes history.
Search still returns the first ten results.

## Linux media controls

MPRIS registers as org.mpris.MediaPlayer2.spotify_tui, even without a tray host or
with --no-tray. Media keys and playerctl can control playback, next/previous, seek,
volume, shuffle and repeat, and read track metadata and position. It continues
after q; Q, stop, logout and updates stop the bridge. The desktop must have a
session D-Bus and the local player must be paired. macOS continues to support the
terminal, mouse and playback features; this release does not add Mac media keys.

```bash
playerctl -p spotify_tui play-pause
playerctl -p spotify_tui next
playerctl -p spotify_tui previous
```

reopen the terminal. The updater verifies and activates the matching Go/Rust pair.
Soloist remains a separate official Spotify download. Linux requires glibc 2.39+;
Mac requires Apple Silicon and macOS 15+. Mac binaries are ad-hoc signed and are
not Apple-notarized. [Setup and controls](https://github.com/wrestle-R/spotify-tui-rdp/blob/v0.5.0/docs/SETUP.md).

## Verification and remaining limits

Go race tests, vet, Rust tests/clippy, isolated real D-Bus transport checks,
packaging and a PTY walkthrough cover this release. The real paired Linux
candidate passed selected-song playback, next/previous, automatic collection
advance and playerctl pause/resume/seek/volume. The terminal screenshot uses only
generic demo music. Native Linux, macOS 15, macOS 26 and website jobs gate publishing.
Hosted Mac checks do not establish real Mac account/audio acceptance.

Cold playback can buffer; the helper now allows 15 seconds for confirmed playback
before reporting an unknown outcome. Spotify may restrict shuffle/repeat actions
for an active context. Genuine offline downloads and long-session stability
acceptance remain unfinished.
